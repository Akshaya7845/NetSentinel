**4. Optimization Recommendations**

| Area | Recommendation | Rationale |
|------|----------------|-----------|
| **Network Path** | • Run traceroute/Path MTU discovery from all client regions.<br>• Engage with upstream ISPs to identify congested links.<br>• Deploy BGP route reflectors or use a CDN to shorten paths. | Reduces RTT and packet loss. |
| **Packet Loss Mitigation** | • Enable ECN (Explicit Congestion Notification) on routers.<br>• Increase MTU to avoid fragmentation.<br>• Implement TCP Fast Open or QUIC for faster handshakes. | Lowers retransmission overhead. |
| **Load Balancing** | • Switch to a **dynamic, weighted round‑robin** or **least‑conn** algorithm.<br>• Add health‑check thresholds that detect high latency before marking a node unhealthy.<br>• Scale horizontally (add more instances). | Prevents over‑loading of single nodes. |
| **Backend Performance** | • Profile CPU/memory usage; add auto‑scaling rules.<br>• Optimize database queries (indexes, caching).<br>• Use connection pooling and keep‑alive. | Reduces server‑side latency and failures. |
| **Caching** | • Implement CDN edge caching for static assets.<br>• Use HTTP/2 server push or gRPC for efficient payloads. | Cuts round‑trip time for repeat requests. |
| **Monitoring & Alerting** | • Add per‑region latency dashboards.<br>• Set alerts for packet loss > 0.5 % and latency > 400 ms.<br>• Correlate logs with network metrics. | Enables proactive issue detection. |
| **Testing** | • Run synthetic traffic from all regions.<br>• Perform load tests to identify breaking points. | Validates improvements before production rollout. |
