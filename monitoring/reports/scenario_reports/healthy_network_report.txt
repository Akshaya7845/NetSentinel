## 4. Optimization Recommendations

Although the network is already healthy, a few proactive measures can further tighten performance and guard against future growth or traffic spikes.

| Area | Recommendation | Rationale | Expected Impact |
|------|----------------|-----------|-----------------|
| **Load Balancing** | Verify that traffic is evenly distributed across all edge nodes. | Minor load imbalances can cause localized spikes. | Reduce P95 latency by ~1–2 ms. |
| **TCP/IP Stack Tuning** | Enable TCP Fast Open, adjust window scaling, and tune buffer sizes on all servers. | Improves handshake latency and throughput. | 5–10 % reduction in average latency. |
| **Connection Pooling** | Ensure that client libraries reuse TCP connections (keep‑alive). | Avoids repeated handshakes. | 10–15 ms per request for new connections. |
| **Edge Caching** | Deploy CDN or edge cache for static assets. | Offloads traffic from origin. | Decreases overall request latency by ~5–10 ms. |
| **Network Path Optimization** | Run traceroute and BGP monitoring to detect sub‑optimal routes. | Detects any routing changes that could increase latency. | Maintain latency stability. |
| **Monitoring & Alerting** | Add percentile‑based alerts (P95, P99) and anomaly detection. | Early detection of latency drift. | Prevent SLA breaches. |
| **Postman Test Environment** | Run Postman from a location closer to production (e.g., same region). | Reduces client‑side overhead. | Align test latency with production. |

> **Note:** All optimizations are low‑risk and can be rolled out incrementally. The most immediate benefit comes from ensuring connection reuse and load balancing.
