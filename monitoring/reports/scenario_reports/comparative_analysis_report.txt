## 3. Performance Analysis

### 3.1 Latency Distribution
- **Mean:** 165 ms – acceptable for many services but above the 100 ms SLA.
- **Median (≈ P50):** Likely ~140 ms (inferred from mean and P95).
- **P95:** 340 ms – 95 % of requests finish under 340 ms; 5 % exceed this, causing user‑visible delays.
- **Max:** 320 ms – indicates outliers; however, max is slightly lower than P95, suggesting a skewed distribution or measurement artifact.

### 3.2 Failure Analysis
- **Failed Requests:** 605 / 15 000 = **4.03 %** failure rate.
- **Error Rate:** 4.1 % – aligns with failed requests; likely due to timeouts, 5xx errors, or network disconnects.
- **Correlation with Latency:** Higher latency spikes coincide with increased failure rate, implying timeouts.

### 3.3 Packet Loss Impact
- **2.1 % loss** leads to retransmissions, doubling or tripling round‑trip times for affected packets.
- **TCP Retransmission** can add 200–400 ms per request, explaining the high P95 and Postman times.

### 3.4 Postman vs. Production
- **Postman Response (395.6 ms)** is significantly higher than average latency, indicating that the client’s environment (e.g., local network, firewall) or the API gateway adds extra overhead.

## 4. Optimization Recommendations

| Area | Recommendation | Expected Impact | Priority |

| **Network** | • Replace or upgrade the affected link (e.g., 1 Gbps to 10 Gbps).<br>• Deploy a dedicated, low‑latency path (e.g., MPLS or SD‑WAN).<br>• Implement QoS to prioritize API traffic.<br>• Run traceroute and path MTU discovery to identify fragmentation. | Reduce packet loss to < 0.5 %, cut retransmissions, lower latency. | **Critical** |

## 5. Final Conclusion

The service is **currently unhealthy** with latency, packet loss, and error rates far exceeding acceptable thresholds. The primary drivers are:

1. **Network packet loss (2.1 %)** causing retransmissions and jitter.
2. **Backend resource contention** leading to high P95 latency and timeouts.
3. **Uneven load distribution** amplifying maximum latency spikes.

By addressing the network path first (upgrade bandwidth, QoS, and path optimization), we can immediately cut retransmissions and reduce jitter. Parallelly, scaling and optimizing the backend, coupled with smarter load balancing, will bring average latency below the SLA and drop the error rate below 1 %. Continuous monitoring and synthetic tests will ensure that any regressions are caught early.
