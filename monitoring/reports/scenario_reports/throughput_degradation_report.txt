   - Avg 145 ms vs. SLA 120 ms → 21 % over target.

3. **Packet Loss Impact**

4. **Postman vs. Service Latency**

5. **Resource Utilization (Hypothetical)**

   - Memory usage near 90 % → GC pauses.

## 4. Optimization Recommendations

| Area | Action | Expected Impact |
|------|--------|-----------------|
| **Network** | • Replace or upgrade the congested link (e.g., increase bandwidth from 100 Mbps to 1 Gbps).<br>• Deploy QoS policies to prioritize critical traffic.<br>• Run a traceroute / path MTU discovery to locate the loss point. | Reduce packet loss to <0.5 %, lower retransmissions, bring latency back to SLA. |
| **Transport** | • Enable TCP Fast Open / keep‑alive to reduce handshake overhead.<br>• Tune congestion window (cwnd) and RTO settings on servers. | Minor latency reduction; helps during transient congestion. |
| **Application** | • Scale horizontally (add more instances) or vertically (more CPU/RAM).<br>• Profile code to identify CPU‑heavy routines.<br>• Implement async I/O for blocking calls. | Lower CPU wait times, reduce GC pauses, improve throughput. |
| **Database / External Services** | • Add connection pooling or increase pool size.<br>• Optimize slow queries (indexes, query plans).<br>• Cache frequent results (Redis, in‑memory). | Decrease downstream latency from ~275 ms to <100 ms. |
| **Monitoring & Alerting** | • Add packet‑loss metrics at the edge routers.<br>• Set alerts for latency > 200 ms, packet loss > 0.5 %.<br>• Correlate logs with latency spikes. | Faster detection of future degradations. |
| **Capacity Planning** | • Perform load testing to determine new thresholds.<br>• Model traffic growth and plan for 30 % headroom. | Ensure system stays healthy under peak load. |
| **Security / Firewall** | • Verify that firewall rules are not dropping packets (e.g., due to rate limiting). | Prevent inadvertent packet loss. |

## 5. Final Conclusion

The service is currently **unhealthy**: latency, error rate, packet loss, and downstream response times all exceed SLA thresholds. The root cause is a combination of **network congestion causing packet loss** and **backend resource contention** (CPU, memory, database). Immediate actions should focus on:

1. **Eliminating packet loss** by upgrading network capacity and applying QoS.
2. **Scaling and optimizing the application stack** to handle current load.
3. **Optimizing downstream services** (database queries, external APIs) to reduce the 275 ms added latency.

Once these changes are applied, re‑measure all KPIs. The goal is to bring average latency below 120 ms, P95 below 250 ms, packet loss under 0.5 %, and error rate below 1 %. Continuous monitoring and capacity planning will prevent recurrence.
