## 2. Root Cause Analysis

### 2.1 Network‑Layer Issues
1. **Packet Loss (1.5 %)**  
   * Causes retransmissions → latency spikes.  
   * Likely due to congested links, faulty NICs, or mis‑configured QoS.
2. **Path MTU / Fragmentation**  
   * Large packets may be fragmented; reassembly adds delay.
3. **Routing Instability**  
   * Flapping routes or sub‑optimal BGP paths can increase hop count.

### 2.2 Transport‑Layer Issues
1. **TCP Retransmissions**  
   * Packet loss triggers retransmissions; each adds ~RTT.  
   * 1.5 % loss → ~1–2 retransmissions per packet on average.
2. **Congestion Window Shrink**  
   * Loss triggers cwnd reduction → slower throughput.

### 2.3 Application‑Layer Issues
1. **Server Overload**  
   * High CPU/Memory usage can delay request handling.  
   * 5 000 requests over a short window may saturate the backend.
2. **Inefficient Queries / Blocking**  
   * Long DB calls or locks increase response time.
3. **Large Payloads**  
   * 720 ms Postman RT suggests large payloads or slow serialization.

### 2.4 External Factors
1. **Client Environment**  
   * Postman RT higher than server‑side latency indicates client‑side network or processing overhead.
2. **Third‑Party Services**  
   * If the application calls external APIs, their latency contributes to overall response time.

## 3. Performance Analysis

| Observation | Implication |
|-------------|-------------|
| **Avg Latency 320 ms vs. P95 651 ms** | 5 % of requests are > 650 ms → heavy tail. |
| **Packet Loss 1.5 %** | Roughly 1–2 retransmissions per packet → adds ~200–400 ms per request. |
| **Failed Requests 35 (0.7 %)** | Correlates with error rate; likely due to timeouts or connection resets. |
| **Postman RT 720 ms** | Client‑side overhead or additional hops; indicates that the server latency is likely lower than Postman RT. |
| **Max Latency 590 ms** | Outlier but still within P95; indicates occasional severe congestion or server stalls. |

**Trend Insight**  
- The latency distribution is skewed; the mean is inflated by a small number of very high‑latency requests.  
- Packet loss is the primary driver of retransmissions, which in turn inflates the tail.

## 4. Optimization Recommendations

### 4.1 Immediate Network Fixes
| Action | Tool / Command | Expected Impact |
|--------|----------------|-----------------|
| **Run traceroute / MTR** | `mtr -r -c 100 <destination>` | Identify hops with high loss or latency. |
| **Check NIC statistics** | `ethtool -S <iface>` | Detect link errors or CRC issues. |
| **Verify MTU** | `ping -M do -s 1472 <dest>` | Ensure no fragmentation. |
| **Inspect QoS / ACLs** | `show policy-map` (Cisco) | Remove mis‑configured bandwidth limits. |
| **Check BGP / OSPF** | `show ip bgp` / `show ip ospf neighbor` | Resolve flapping routes. |
